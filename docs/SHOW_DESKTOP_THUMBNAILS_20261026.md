# Win+D 层级恢复与合并入口缩略图

## 本次窗口诊断

用户再次反馈 Win+D 后收纳区消失。已安装程序的本地日志表明，收纳层仍然可见、未最小化、未 cloak，命中区域仍有 5 个；收纳区配置可见且没有全部开启自动隐藏。因此这次针对原生层级恢复处理。

日志中反复出现：收纳层已经带 TOPMOST 标志，但其枚举位置仍在被抬升的 Progman 之后。旧逻辑只在没有该标志时执行提升，而且会把宿主之后的其他 TOPMOST 标志窗口也作为插入目标。还记录到外部窗口插入返回 `0x80070005`（访问被拒绝），原逻辑没有兜底位置。

## 修复

- 同时检查真实枚举位置；收纳层在宿主之后时，即使已经带置顶标志，也重新请求提升。
- 插入目标仅从宿主之前选择，避免按标志选到桌面后面的窗口。保留任务栏、菜单及桌面上方覆盖层的位置。
- 普通层级插入失败时，退到本进程不可见的普通层级标记之后；该标记无效则退到底部，避免长期留在置顶状态。已经处于兜底位置时不重复定位。
- 仍仅在桌面、受信任务栏或菜单交互下临时提升；切回普通应用、暂停或宿主失效时撤销。没有改成永久置顶，也没有激活窗口、修改父窗口或改变文件配置。
- 新日志标记为 `20261026-show-desktop-order`，便于区别旧版本现场。

## 缩略图入口

「合并到最后一项」改成前四个剩余项目的 2×2 图标预览，使用与正常条目相同的缓存图标和缺失图标兜底。点击后仍打开全部剩余项目。配置内部值继续沿用 `folder`，已有选择无需重新设置。

## 验证

- 新增不可见原生窗口回归：层已经 TOPMOST，但被抬升宿主排在其前面。旧代码失败，修复后层位于宿主之上、覆盖层之下，并且焦点、前台和可见性不变。
- 新增现场混合顺序回放，确保宿主之后带 TOPMOST 标志的外部窗口不会成为插入目标。
- 230 项前端测试、75 项原生测试通过，2 项原有忽略；Rust 全目标检查通过。
- 浏览器内存验收：缩略图含 4 个已加载的缓存图标，裁切数为 0；点击后展开 28 项，首屏 18 项完整显示。
- 仍需要换用本次构建重复 Win+D 验证用户机器上的偶发场景，原生窗口回归不等同于已在现场确认根治。

窗口定位 API 约定：[SetWindowPos](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowpos)。
