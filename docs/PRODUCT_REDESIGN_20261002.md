# Nestra 功能重设计

状态：第一阶段核心功能与 Nuxt UI 已实施，实机验收边界见 [实施记录](REDESIGN_IMPLEMENTATION_20261002.md)。日期：2026-10-02。

用户要求：参考 SnowDesktop 重新设计整个系统的功能模块，设计完成后再替换 UI。此前选定的 Nuxt UI 保留为组件方案，页面结构由本设计决定。

## 1. 产品目标与范围

帮助 Windows 用户完成三个连续任务：整理桌面上的文件、从多个来源找到项目、快速访问常用项目。桌面负责日常操作，控制中心负责创建、配置和诊断；两者访问同一套功能。

默认保留原生桌面图标。首次启动不移动任何现有文件、不创建预填充的收纳区、不开启自动整理。多显示器作为正常使用场景，撤销配置和恢复布局有明确入口。

阶段建议：第一阶段形成整理、搜索、快捷启动、小组件与布局备份的完整产品；第二阶段增加完整 Dock 和窗口访问；第三阶段扩展小组件与插件。按获准开始的阶段方案实施；完整 Dock 保留在第二阶段。

## 2. 对照依据与当前问题

本次参考固定到 SnowDesktop 提交 `b0d6c593eb79728803d585a57627e0aa72abca76`，依据公开 README 和源码，未安装运行参考项目。因此以下是产品结构和实现规则对照，不是实机体验评分。

| 领域 | 当前项目代码中的事实 | 新设计 |
| --- | --- | --- |
| 功能入口 | 管理器只有收纳区、布局、外观、常规、关于五个页签 | 以用户任务组织控制中心，启动、搜索、小组件和数据都有独立入口 |
| 文件来源 | `CustomGroupDefinition` 同时表示真实收纳区与已有文件夹，靠 `mappedPath` 区分 | 把文件来源、面板呈现和聚合关系分开 |
| 文件组 | `tabGroups` 支持切换，但借用首个成员的布局，排序需要迁移面板布局 | 文件组拥有独立布局；来源顺序不改变面板身份 |
| 分类 | `matchesFilter` 按扩展名筛选单个面板，不移动文件 | 分类视图与整理规则分别命名；提供桌面来源的分类视图 |
| 快捷启动 | 单个引用面板，有单击启动、全部启动和移除；控制中心仅有显示开关 | 增加项目管理、排序、快捷集合和失效入口处理 |
| 搜索 | 已接入 Everything IPC；管理器和桌面各有搜索状态；“应用”只覆盖桌面及收纳区应用 | 共用一个导航模型，提供真正的应用目录和明确的搜索来源状态 |
| 小组件 | 便签、待办、剪贴板已存在，创建主要走托盘事件；桌面渲染没有按 `layout.visible` 筛选 | 统一组件中心，提供创建、显示、隐藏、定位、编辑与删除 |
| 运行状态 | `paused` 实际隐藏桌面层并恢复原生图标，界面叫“暂停整理” | 明确叫“隐藏 Nestra 桌面”；自动整理暂停是另一项状态 |
| 多屏 | 有显示器分配、平铺、层叠与越界恢复 | 加入显示器示意、定位、锁定和断开显示器后的回收区 |
| 备份 | 命令与管理器没有配置导出/恢复流程 | 提供配置备份、恢复预览、路径重绑定与恢复前快照 |

  快捷启动                 固定项目、快捷集合、顺序、失效入口
  搜索与导航               搜索范围、提供方状态、应用目录、热键

控制中心导航分为“桌面与文件”“效率工具”“偏好与数据”三组，不把九个入口挤成一排。所有桌面对象都有“在控制中心管理”入口，直接定位对应实例；热键打开搜索不切换用户当前的配置页。

### 桌面总览

展示真实状态：Nestra 桌面显示状态、共存/专注模式、当前显示器、隐藏面板数量、不可用来源、Everything 连接状态。主操作是“添加桌面内容”和“定位面板”。不放没有用途的图表和虚构效率分数。

### 文件与收纳

列表按收纳区、映射、分类视图、文件组筛选，行内只放名称、类型、来源路径、状态、显示开关和更多菜单。修改来源、拖入策略、筛选和显示方式进入详情。已隐藏对象始终可在控制中心恢复。

“添加桌面内容”先选择四种任务：新建收纳区、显示已有文件夹、按类型查看桌面、组合多个来源。分别解释实际行为，不让用户通过同一个“新建分组”下拉菜单猜测。

文件组详情用来源列表添加、移除、排序，支持“全部来源”聚合搜索和单来源标签。删除文件组只拆除组织关系，保留来源和文件。移除一个来源后，组的布局保持稳定。

### 快捷启动

独立管理应用、文件、文件夹与快捷集合。支持从搜索结果固定、拖入、浏览选择、键盘排序、编辑显示名称和移除引用。显示实际路径与有效性。

失效入口保留为“找不到项目”，允许重新绑定或移除；不因临时断盘或网络目录失联自动删除。现有 `launcherIds` 自动清理失效引用的行为需要调整。

“启动整个集合”展示项目数量；逐项结果区分成功与失败，避免同时打开大量项目却只给一个成功提示。第一阶段以启动条呈现；完整 Dock 另有运行应用、窗口预览、激活、最小化、关闭、自动隐藏和边缘停靠验收。

### 搜索与导航

一个搜索流程覆盖控制中心、桌面按钮和全局热键。全局唤起使用正常可激活的独立搜索窗口，避免在其他应用前台时先打开完整控制中心；桌面原位搜索仍遵守桌面输入授权。

用户可选：全部、应用、桌面、收纳区、映射文件夹、全盘文件。“全盘文件”指 Everything 已索引的范围，不承诺所有盘符、网络目录或全文检索。

提供方独立报告可用、查询中、未安装/未运行、超时、受限范围。Everything 未连接时，本地结果照常展示；在结果区说明当前覆盖范围，在搜索设置提供重新检测和官方安装说明。软件不自动下载或启动外部程序。

应用目录至少包含个人/公共开始菜单、应用快捷方式和 Windows 已安装应用入口；不能把桌面 `.lnk` 列表叫“已安装应用”。真实应用目录完成之前，旧入口继续使用“桌面应用”的准确标签。

结果显示图标、名称、来源、完整路径，并区分同名文件。支持 ↑↓ 选择、Enter 打开、Esc 关闭，以及打开所在位置、复制路径、固定到快捷启动。外部搜索结果默认只提供访问与固定；移动、重命名和回收需要重新验证路径及操作权限。

按规范化路径去重，同时保留多个来源归属。本地结果先显示，慢提供方完成后增量合并，键盘选中项按稳定身份保留；新查询取消或忽略旧结果。结果上限、映射递归范围和超时在状态中明确，不把截断当成完整结果。

### 小组件

第一阶段提供已有便签、待办、剪贴板，并增加轻量时钟；组件中心区分“可添加类型”和“已添加实例”。实例可命名、显示/隐藏、定位、更换显示器、编辑内容和删除。

隐藏保留内容；删除便签和待办要展示内容将被移除的确认。剪贴板是共享历史，多个视图不创建多个采集器；移除视图不等于清空历史。提供采集开关、暂停、数量限制和清空入口，文本历史继续只存在内存、不进入配置备份。月历、番茄钟、媒体和系统监控后续扩展，插件目录不在未实现时伪装成商店。

### 布局与显示器

用显示器示意选择目标，每个对象都能定位、平铺、层叠、对齐、恢复默认位置与锁定。锁定阻止移动和缩放，文件操作仍可使用。拖入显示器边缘有明确边界反馈。

断开显示器后，把其对象临时放进可见显示器的“待恢复”区；保留原分配，显示器恢复后可回迁。使用稳定显示器身份及屏幕内坐标，处理负坐标、DPI 和工作区；“恢复布局”不删除对象内容或文件。

### 外观、数据和系统

Nuxt UI 用于控制中心控件和导航，蓝色强调、灰白底色；桌面用更轻的材质。桌面与管理器共用字体、间距、图标和状态颜色，桌面透明度不影响控制中心文字可读性。管理器主题和桌面材质分别配置，外观有实时预览与重置。

数据页管理配置备份，明确“不包含原文件”。导入先检查版本，再列出新增/修改对象、缺失路径、显示器变化、小组件内容变化及外观变化。恢复前保存当前配置快照。备份不包括剪贴板、Shell 图标缓存或 Everything 结果。

系统设置集中管理开机启动、共存/专注模式、快捷键、诊断与版本。关闭窗口隐藏到托盘，退出才终止进程并恢复原生图标。原“暂停整理”改为“隐藏 Nestra 桌面”，其含义不与整理规则暂停混用。

## 4. 文件行为契约

| 目标或动作 | 预览和默认结果 | 移除时的行为 |
| --- | --- | --- |
| 收纳区 | “移动到：桌面\\.nestra\\区名”；真实移动，成功后迁移条目引用 | 使用“解散收纳区”，先放回文件；全部成功后才移除目录和对象 |
| 新建映射 | 默认浏览模式；拖入显示“不接收文件” | 使用“移除映射”，只删视图，保留目录和内容 |
| 开启接收文件的映射 | 明确选择移动/复制；每次拖入展示动作和完整目标路径 | 移除映射仍只删视图；现有映射升级保留旧移动策略并清晰标注 |
| 分类视图 | 只筛选展示；不作为模糊的移动目标 | 移除视图不改文件位置 |
| 文件组 | 只有具体标签对应可写目标时才接受拖入；“全部来源”没有唯一目标，需要选择 | 解散文件组不解散其来源 |
| 快捷启动或快捷集合 | “添加引用，原文件不移动” | 移除引用不删文件 |
| 收纳区项目“放回桌面” | 验证后移回 Known Folder 的个人桌面 | 成功后更新路径、排序、折叠和固定引用 |
| 映射或分类项目拖向桌面空白 | 默认不执行；需要显式选择文件操作 | 防止把浏览已有目录误变成移动文件 |
| 文件“移到回收站” | 唯一文件删除入口，明确确认目标 | 按系统回收站行为处理 |

批量操作先显示计划，逐项记录结果。同名默认保留两份并显示最终名称，禁止静默覆盖；被占用、权限不足、目录放入自身、重解析路径循环都要在后端处理。操作进行中不提交成功状态；部分成功后保留失败项，允许重试失败项，不能重新执行已成功的项目。

整理规则第一阶段提供手动预览与执行：选择来源、类型/名称条件、目标收纳区 → 显示将移动的项目 → 确认执行 → 逐项结果。自动执行属于后续能力，默认关闭；没有完成预览和失败处理之前不开放“自动整理”开关。

## 5. 核心流程

### A. 首次使用与真收纳

打开控制中心 → 选择新建收纳区 → 命名并显示实际目录 → 创建空面板 → 拖入一个文件，预览移动目标 → 移动成功 → 双击打开 → “放回桌面” → 重启后验证布局和引用。

已有文件不会因为创建面板自动消失。空面板提示可拖入什么、将发生什么；失败状态保留原文件位置和可重试入口。

### B. 项目工作区

显示已有文件夹 `D:\\项目资料` → 默认只浏览 → 新建文件组“工作” → 加入该映射与“待处理”收纳区 → 在全部来源中查找报告 → 按来源访问或固定到快捷启动。分组、筛选、改显示名称都不移动文件。

### C. 全局查找

在任意应用按 Ctrl+Alt+F → 打开紧凑搜索窗口并获得键盘输入 → 输入“报告” → 先返回本地结果 → 合并 Everything 已索引结果 → 查看路径后 Enter 打开。Everything 不可用时保留本地结果和准确范围提示。

### D. 隐藏与恢复

隐藏面板/小组件 → 控制中心仍列出该对象 → “显示并定位”恢复到有效屏幕 → 原内容和布局保留。隐藏整个 Nestra 桌面也不影响搜索和控制中心。

### E. 备份恢复

导出配置 → 另一台机器导入 → 预览缺失路径和显示器 → 为映射重新选择目录 → 为收纳区绑定现有目录或新建空目录 → 保存恢复前快照 → 应用配置。不能按旧备份里的区名自动重命名当前真实目录，不能因配置中缺少某区而删除或解散现有目录。

## 6. 模块与数据模型

目标模型区分五类对象：

- 文件来源：`ZoneSource`、`FolderSource`、`DesktopSource`；描述文件在哪里及可用性。
- 视图：`SourceView`；描述筛选、排序、网格/列表，不拥有文件。
- 文件组：`FileGroup`；引用多个视图，有自己的布局和活动来源。
- 快捷集合：`LaunchCollection`；引用项目，不继承来源的文件操作权限。
- 桌面呈现：`SurfaceLayout`；记录对象身份、显示器、位置、尺寸、显隐和锁定。

小组件内容、搜索提供方状态、运行状态分别维护。临时搜索结果和窗口句柄不得进入权威文件成员集合；剪贴板内容不进入持久化配置。

控制中心和桌面都是这些模块的客户。共享动作服务处理创建、文件移动、固定、定位和显隐，不在两种界面各写一套业务逻辑。

建议责任边界：

```text
src/domain/       来源、视图、文件组、快捷集合、组件、布局的类型与约束
src/features/     各模块动作、状态和页面
src/services/     搜索聚合、文件操作、配置、图标、跨窗口同步
src/desktop/      桌面呈现与拖放接入
src/manager/      控制中心与稳定导航路由
src-tauri/        路径验证、真实文件操作、Shell、窗口与索引接入
```

先从现有大 store 提取可独立测试的模块，旧入口通过适配器继续可用；无需在第一步把所有目录一次搬迁。跨窗口仍通过后端事件和三方合并同步，写盘继续串行。

## 7. 旧配置迁移

引入 `schemaVersion: 2`，迁移前写备份；迁移可重复执行，版本校验失败保留旧配置。迁移只调整配置，不能在打开新版时自动搬动用户文件。

1. `customGroups` 无 `mappedPath` → 收纳区来源；有 `mappedPath` → 文件夹来源。保留 id、实际路径与筛选。
2. `tabGroups` → 独立文件组，初次继承原锚点布局；后续排序不再借用首个来源的位置。来源可以独立显示或加入一个文件组，不因引用而改变文件归属。
3. `launcherIds` → 固定项目引用，保留顺序和稳定身份；无法解析的入口保留待修复，不能当幽灵文件成员删除。
4. 便签/待办/剪贴板视图 → 小组件实例，保留内容和布局；剪贴板历史继续不迁移、不落盘。
5. 原生图标设置 → 共存/专注模式；继续携带 `coexistMigrated: true`，不触发重复复位。
6. 新集合字段全部纳入 `mergePersisted`，远端套用仍抑制回写。路径变更继续经 `migrateItemId` 迁移用户引用。
7. 未配置但磁盘中仍存在的收纳目录进入“发现未关联收纳区”列表，允许重新接入；不得当成垃圾目录删除。

## 8. 实施顺序与交付门槛

### 第一阶段：可用产品主链路

1. 确认当前真收纳链路实机门槛，保留以前没有通过的拖放和桌面输入项目。
2. 建立来源、视图、文件组的类型与迁移适配；提取共享动作与稳定路由。
3. 实现控制中心的信息架构、快捷启动管理、小组件管理与隐藏恢复；此时接入 Nuxt UI，不先给旧页签换皮。
4. 完成统一搜索、已安装应用目录、提供方状态和独立搜索窗口。
5. 完成来源组合、分类视图、手动整理预览、批量结果和可见的文件策略。
6. 完成多屏定位、锁定、配置备份恢复和路径修复。
7. 统一桌面面板、菜单、搜索和系统提示的视觉与行为。

每一项分别记录“设计完成 / 已实现 / 自动测试通过 / 实机验收通过”，不靠构建成功宣称功能可用。

### 第二阶段：完整 Dock

边缘停靠、自动隐藏、临时唤起、固定项目与运行应用分区、窗口预览和窗口控制。运行窗口需要单独身份与生命周期，不能以固定快捷方式是否存在推断应用运行状态。是否并入第一阶段按用户选择更新。

### 第三阶段：扩展

月历、番茄钟、媒体、系统监控、更多布局预设、经过预览机制验证的自动整理、组件包安装和插件生命周期。任务栏改造、Lua 和创意工坊单独评估，不作为第一阶段基础依赖。

### 验收场景

| 场景 | 必须观察到的结果 |
| --- | --- |
| 新建收纳区 | 原桌面文件保持原位；空区可定位和恢复 |
| 原生拖入/跨区移动/放回桌面 | 磁盘各处只有正确份数；打开内容一致；取消拖动不移动 |
| 解散收纳区遇到被占用文件 | 保留区及失败项；已返回文件不重复搬；不出现虚假成功 |
| 映射浏览与移除 | 浏览模式拒绝拖入；移除后原目录及文件完整 |
| 文件组排序与移除来源 | 面板位置不跳；来源仍存在；活动标签有效 |
| 全局搜索与中文输入法 | 其他应用前台也能输入；Esc 正确关闭并归还焦点 |
| 搜索降级与快打查询 | Everything 超时不阻塞本地；旧结果不覆盖新词；路径可区分同名结果 |
| 固定外盘项目后拔盘 | 显示不可用并能重新绑定；入口不被自动清理 |
| 小组件隐藏、重启、恢复 | 内容保留；隐藏对象不渲染；删除与隐藏分别处理 |
| 两个窗口连续修改 | 不回写乒乓；不冲掉未保存操作；新增模型参与三方合并 |
| 拔屏与 DPI 改变 | 对象可找回且可操作；恢复后可回迁，不永久改写原屏幕布局 |
| 导入旧配置或缺失目录 | 先有恢复预览和当前备份；不移动、删除或误重命名原文件 |

功能验证使用隔离临时文件，不批量试验用户真实桌面。前端 `pnpm build`、Rust `cargo check` 和相应测试通过后，再记录原生拖放、Shell、焦点和多屏实机结果。
