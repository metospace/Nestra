## 服务对象和任务边界

面向中文 Windows 个人桌面用户，主要任务是整理项目资料、找到并打开文件、准备常用入口、记录和完成临时待办。

必须保留真实收纳与只浏览的区别、同名文件不覆盖、解散前放回文件、快捷启动只保存引用，以及已保存内容和布局保持一致。目录名称、面板、来源和标签页是实现方式；用户无需先理解内部模型才能开始使用。

## 本次实测问题及具体建议

### 1. 待办“内容会自动保存”会让用户误以为修改已保存 — 必须修复

复现：组件 → 编辑今天的待办 → 点击已有任务文字 → 修改 → 不点保存直接关闭 → 切到桌面空间 → 回到待办编辑。

实际：新增内容保留，修改草稿消失。编辑器顶部始终显示“内容会自动保存”，编辑行另有“保存/取消”，未明确说明两种保存方式。证据：[编辑中](customer-ui-evidence-20261005/todo-unsaved.jpg)、[重新进入](customer-ui-evidence-20261005/todo-after-return.jpg)。

影响：容易误判保存状态，需要重新输入，损失的是尚未提交的修改，不能描述成已保存任务被删除。

改进：顶部明确“新增和完成状态自动保存；修改文字请点击保存”，编辑行显示“尚未保存”；关闭或切换模块保留草稿，重新进入可继续编辑。保留空内容和并发冲突校验，冲突时保留用户草稿供选择。

改进前：用户要记住不同操作的保存规则。改进后：用户能看到保存状态，离开后仍可继续修改，无需重录。

### 2. 固定入口成功后缺少“在哪里用”的下一步 — 优先优化

复现：保持启动栏默认隐藏 → 桌面搜索 → 固定任意示例文件 → 查看成功提示 → 到控制中心快捷启动页查找显示入口。

实际：固定成功且原文件不移动，但启动栏显示状态仍为 false；成功提示没有显示动作，快捷启动页没有显隐开关。证据：[固定结果](customer-ui-evidence-20261005/pin-hidden-result.jpg)、[快捷启动页](customer-ui-evidence-20261005/launcher-hidden.jpg)。桌面测试页面本身不渲染启动栏，因此隐藏判断依据是页面公开的验收状态，不能以“此页没画出来”单独推断正式桌面状态。

影响：增加寻找设置和跳转的负担。用户完成了固定，仍需要自行查明如何使用入口。

改进：成功提示加“显示桌面启动栏”；快捷启动页加“在桌面显示”开关和“查看启动栏”。保留用户已选择的隐藏状态，由用户明确显示后保存；不要每次固定都强制弹出。

改进前：固定后另找概览或布局开关。改进后：固定成功后一步显示，之后日常直接启动。

## 已经简单、应保留的体验

- 新建收纳区只填名称，空名称禁用提交；同时说明拖入会移动文件。
- 添加任务按“新建收纳区 / 显示已有文件夹 / 按类型查看 / 组合来源”区分，明确哪些会移动文件。四种能力无需删掉，首次欢迎状态仍待验证。
- 待办 Enter 添加、持续保持输入焦点、已完成折叠、删除撤销，适合重复使用；无需强加日期、标签和优先级。
- 搜索结果展示完整路径，键盘提示明确，无结果也能调整条件后继续。
- 固定提示清楚说明原项目不移动，保留这一安全表达。

## 不能据本轮宣称通过的项目

- 全新空配置的首次引导；本次管理页已有示例收纳区。
- 实际创建目录、Explorer 外部拖入、跨区移动、拖出、放回和解散，以及同名/占用/权限失败处理。
- Everything 延迟补入后的选择稳定性；现有桌面 fixture 不返回延迟索引结果。
- “在桌面查看”的实际位置变化和锁定对象处理。
- Windows 全局热键、中文输入法、桌面焦点交还、OLE 拖放。浏览器填入中文不代表原生输入法通过。
- 多显示器、跨窗口三方合并、实际写盘、重启恢复、备份导入恢复和失联入口重绑。

本轮未修改产品源码，未实施优化。新增内容仅是本报告和界面截图；之前已有工作区改动不属于本轮实施。
