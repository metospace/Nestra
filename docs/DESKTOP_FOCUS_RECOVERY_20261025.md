# 偶发桌面输入失败的恢复

用户确认截图中的「暂时无法获取键盘焦点」有时伴随实际无法输入，因此除修正提示位置外，继续补充输入会话恢复。

## 改动

- 仍复用全局 `installDesktopInputFocus` 协调收纳区改名、搜索、便签和其他桌面编辑器，保持原生 grant/release 串行。
- 一次申请失败不再立即放弃：先等待归还焦点完成，再按 80ms、160ms 延迟重试，总计最多三次申请。持续失败仍显示提示。
- 延迟可取消，切换应用、关闭/禁用输入框或选择其他编辑器后，旧请求不能继续恢复 DOM 焦点。
- 原生侧核对前台窗口在挂接线程、设置焦点期间是否变化；前台不存在、WebView 子窗口未就绪时返回失败，不把外层窗口聚焦当成输入成功。
- 已超时且尚未开始执行的窗口线程请求失效，避免排队回调事后取得焦点。
- 失败阶段记录到现有的有界诊断日志：包括窗口句柄、类名、线程和错误码，不记录窗口标题、输入文字或按键。

## 验证与限制

- 230 项前端测试通过，其中 16 项输入会话测试覆盖瞬时失败恢复、最多三次、取消等待、切换编辑器、切换应用和清理顺序。
- Rust 全目标检查通过，73 项原生测试通过、2 项原有忽略。
- 内存验收页面 `tests/fixtures/desktop-focus-recovery.html` 中，双击标题后前两次申请失败、第三次成功；未再次点击输入框，直接输入「焦点恢复成功」，没有弹出失败提示。
- 浏览器内存验收验证的是恢复流程，不能证明用户机器上的全部 Windows 焦点异常已根治。现有日志没有记录旧版本失败的具体阶段，需要使用新版复测；若仍发生，新日志可区分线程挂接、窗口就绪、前台变化和真实设置焦点失败。

参考 Windows 官方 API 约定：[AttachThreadInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-attachthreadinput)、[SetFocus](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setfocus)。
