# 收纳区手动拉伸恢复

自动适应内容曾移除边缘拉伸入口，导致用户无法控制收纳区大小。本次恢复共享的八方向 `ResizeHandles`，没有引入新依赖。

- 鼠标拖动收纳区任一边缘或四角，立即切换为手动大小，并通过现有持久化链保存 `autoSize: false`。
- 手动模式根据可用宽度重新分列，只展示完整图标行；空间不足时分页，不出现右侧滚动条。
- 新增文件、重新扫描及重载保留手动尺寸。最小尺寸保证一行完整图标及必要的分页栏，越出屏幕时仍受显示器范围约束。
- 「此栏样式与布局 → 布局 → 自动适应内容」可重新开启自动宽高。锁定后禁止移动和拉伸；自动隐藏设置仍独立生效。
- 旧配置没有 `autoSize` 字段时继续沿用自动模式，首次手动拉伸后保存选择。

## 验证

- 前端测试 219 项通过，包含手动尺寸跨内容变更及序列化重载、容量换列、分页完整性、配置校验与恢复自动模式。
- 浏览器使用生产桌面组件及内存数据，实际拖动右下角、右侧和底边；尺寸依次为 356×346、488×346、488×402，新增文件后尺寸保持。
- 检查渲染区域：裁切图标 0 个，内容区域 overflow 为 hidden；恢复自动模式后重新适应完整内容。
- 手动验收入口：Vite 下访问 `tests/fixtures/organizer-resize.html`，不读写真实桌面文件。
