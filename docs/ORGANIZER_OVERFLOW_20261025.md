# 收纳区溢出文件夹与提示位置

## 使用

打开收纳区标题上的设置 → 布局 → 空间不足时，选择「合并到最后一项（文件夹）」。默认仍为分页，每栏独立保存。

超过当前容量时，最后一个单元格显示「更多项目（数量）」。点击后用现有 Nova Dialog 展开剩余项目，复用 ItemTile 的打开、右键、重命名和拖动能力；项目很多时，在展开窗口内分页访问。不会创建真实子目录，也不会移动文件。

拉伸收纳区会重新计算容量，文件顺序保持不变。搜索针对全部项目，原先收进文件夹的匹配项可以直接显示；过滤后能放下全部结果时，不显示多余的文件夹入口。自动隐藏在展开文件夹时保持可见，关闭后恢复原有行为。

## 图 1 问题

原提示固定在覆盖整个虚拟桌面的 WebView 底部 24px，任务栏仍会覆盖其下半部分。本次通过 Tauri 现有 Monitor.work_area 接口获取可用区域，使用桌面层的缩放及虚拟桌面原点统一转换。

提示放在主显示器工作区底部上方 16px；此栏设置放在所属显示器的工作区内，适配任务栏在底部、顶部和侧边。此改动修复提示的显示位置，未改变键盘焦点失败的判定或屏蔽错误提示。

- 226 项前端测试通过，覆盖配置独立保存、序列化恢复、最后一格预留、项目顺序及完整性、容量变化和工作区边界。
- Rust 全目标检查通过；原生测试 73 项通过、2 项原有忽略。
- 内存验收页面 `tests/fixtures/organizer-overflow.html`：35 项分为 7 项直接显示及 28 项汇总；展开的两页可访问至第 35 项。文件移动调用为 0，裁切图标为 0，内容无滚动条。
- 实际拉伸到 516×400 后，最后一格自动汇总 21 项；搜索「项目 35」可直接找到原先折叠的条目。切换回分页保留手动尺寸。
- 模拟底部任务栏高 64px，提示下边界为 640px，任务栏上边界为 656px；设置面板下边界为 644px，均完整显示。
- 文件夹内右键收入折叠后，再从更多菜单展开折叠项目，条目正确提供「取消折叠」。验收同时修复标题栏误处理 Portal 菜单事件的问题：菜单点击不再启动移动手势或触发标题重命名。

沿用现有组件、图标及布局计算，没有增加依赖。
