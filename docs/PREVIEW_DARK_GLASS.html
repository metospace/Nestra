对比度实测

深色玻璃最坏的情况是压在浅色壁纸上 —— 合成底被壁纸提亮，文字对比度跟着掉。下面是浏览器内实时实算的读数，正文一律要求 ≥ 4.5:1。切右上角壁纸按钮可看两种壁纸下的结果。

合成底 = 面板底 rgba(18,20,28,.72) 叠加在壁纸平均色之上；壁纸平均色取渐变壁面的加权近似。

落地铁律：只动 transform / opacity；backdrop-filter 只允许出现在固定或绝对定位的表面（面板 / 菜单 / 弹层），滚动容器绝不加 —— 桌面层是多 WebView 叠在壁纸上的，滚动容器加模糊会持续触发 GPU 重绘。现状的 .nx-body 已按此实现。

两种蓝同时在屏幕上。面板的 token 强调色是 #2563eb，但 tab 选中态 OrganizerPanel.vue:224 直接写死了 rgba(122,162,247,.22)（东京蓝），折叠条底色、选中磁贴底色也是同一片东京蓝。根因是 style.css 第 13 行的深色 token 和第 631 行的浅色 token 并存，后者覆盖 :root 但没覆盖这些硬编码。
2
hover 反馈在默认主题下几乎不可见。.tile:hover 是 rgba(255,255,255,.07) + rgba(255,255,255,.09) —— 这是为深色玻璃写的，却压在 rgba(255,255,255,.817) 的浅色面板上，等于没有。
3
6 条横条把面板切碎。头 / tab / 搜索 / 选择 / 折叠 / 页脚各占一行，每行都是 1px 线或色块，真正的内容网格被压到只剩一半高度。
4
浮层底色游离在体系之外。拖拽反馈 rgba(20,27,39,.96)、重命名框等 12 处是写死深色，不随主题变。浅色面板上会弹出一个纯黑框。
5
字阶与圆角没有系统。字号 8 档乱数（10 / 10.5 / 11 / 11.5 / 12 / 12.5 / 13 / 13.5px），圆角 6 / 7 / 8 / 9 / 10 / 12 / 14 / 16px 混用，box-shadow 13 种写法。
