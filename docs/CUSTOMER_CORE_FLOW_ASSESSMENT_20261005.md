# Nestra 核心流程客户视角评估 · 2026-10-05

当前不建议作为“已经完成客户体验验收”的版本正式交付。最高优先级问题是：搜索结果补入时丢失客户选择、查看面板会改写已安排的位置、批量移动失败缺少完整且可保留的处理结果。

## 使用者、任务与必须保留的要求

目标使用者是需要整理桌面文件、迅速找资料和打开常用应用的 Windows 个人用户，包括办公人员、项目工作人员，以及经常记录临时事项的人。企业审批、多人共享、提醒调度不属于现有文档明确的核心范围。

| 客户完成的任务 | 必須保留的业务要求 | 当前实现方式及可简化空间 |
| --- | --- | --- |
| 把桌面资料整理好并能找回 | 收纳真实移动；结果明确；同名不覆盖；失败保留文件 | 收纳区目录和面板是实现方式，创建流程无需用户理解“来源”“视图”等内部关系 |
| 查看项目文件夹，不搬走原资料 | 默认只浏览；移除面板不删文件 | “文件夹映射”是实现名称，可以用“把文件夹显示到桌面”作为主要业务表达 |
| 把几个项目来源放在一起使用 | 组合不移动文件；来源与布局保持稳定 | 文件组和标签页是实现方式，不应要求用户逐个往返详情页配置关系 |
| 找到并打开正确文件 | 名称、路径、范围明确；结果变化不能改变客户已作出的选择 | 多提供方、异步合并是系统复杂性，不能让用户等待后重新选择 |
| 一次准备好常用入口，每天快速打开 | 固定只存引用；失联保留并能重绑 | 启动栏默认隐藏可以保留，但首次固定后应有直接的显示入口 |
| 记录、修改、完成待办 | 内容保留；删除可恢复；保存状态可理解 | 自动保存与显式保存可以并存，但界面须明确草稿尚未保存 |
| 临时隐藏后继续使用；迁移或恢复配置 | 隐藏保留内容；查看不破坏布局；配置备份不冒充文件备份 | 定位、移动到左上角和显示应是不同动作；恢复前检查与必要确认应保留 |

## 按重要程度排列的问题

### 1. 搜索结果补入后，客户选中的文件变了 — 必须修复

**场景和待实测步骤**：搜索“报告”；本地先返回“报告 A、报告 B”；按方向键选中 B；Everything 稍后返回更多结果；按 Enter。

**当前证据**：`src/features/SearchPanel.vue:19` 中 `queue` 先清空结果，随后捕获一次 `selected`，每次结果补入都按这个旧值计算选择。它没有读取补入前客户当前选择。直接执行该函数，先把本地选择置为 B，再返回索引结果，输出由 B 变成 A（证据 case `local_selection_then_index_results`）。

**影响**：容易打开错误资料，破坏高频“选择后 Enter”的任务。客户即使业务判断正确，也可能因系统刷新而操作错误。

**具体建议**：每次同一查询的结果补入前，按稳定项目身份保留当前选择；只有输入新关键词、切换范围或当前项目确实不再存在时才重置。项目消失时明确提示并采用可预测的选择。保留过期查询隔离和路径区分。

**改进前后**：现在需要等搜索完成后重新确认选择；改进后可以在首批结果中选中并打开，后台补入不改变选择。Windows 原生键盘流程仍须回归。

### 2. “在桌面查看”会重排客户的桌面 — 必须修复

**场景和待实测步骤**：把“项目资料”面板拖到屏幕右侧并锁定；到控制中心选中它；点击“在桌面查看”；再次查看位置。

**当前证据**：`src/manager/WorkspaceOverview.vue:57` 将该按钮接到 `locateSurface`；`src/stores/state.ts:1830` 无条件把位置改到显示器左上角并保存。内存复核中，锁定面板从 `(580,320)` 变为 `(28,76)`，锁定仍为 true（case `click_view_desktop_on_locked_panel`）。该函数也没有隐藏控制中心；用户是否能立即看见桌面仍待实测。

**影响**：降低效率、破坏客户已经排好的布局。客户点击的是查看，系统执行的是移动；锁定的预期也被绕过。

**具体建议**：“在桌面查看”仅显示目标、临时标识目标并让用户看见桌面；隐藏且位置有效的对象按原位恢复。增加独立的“移到屏幕可见处”或“移到左上角”动作。越界对象允许安全找回，但不对正常可见且锁定的对象强制改位。

**改进前后**：现在查看一次可能需要重新拖回、重新排布；改进后直接查看，原位置不变，仅失联屏幕或越界情况需要恢复位置。

### 3. 批量整理失败后，客户缺少完整处理清单 — 必须修复

**场景和待实测步骤**：把多个文件拖入收纳区，其中至少两个模拟被占用或权限不足；等待提示消失；查明失败文件并重试。另测面板多选“移动到…”和批量“放回桌面”。

**当前证据**：`src/stores/state.ts:1293` 的外部拖入只展示失败数量和第一项错误；`showStatus` 在 3 秒后清空。`batchMoveItems` 在结束时用汇总覆盖具体错误；复核最后可见消息只有“1 项成功，1 项未移动”（case `partial_batch_failure`）。失败项仍被选中是一个已有保护，应保留。`OrganizerPanel.vue` 的批量放回逐项调用，缺少一次完整汇总。`FileMoveHistory.vue` 只记录成功移动，无法还原失败原因。整理预览有逐项结果及重试入口，但常用拖放没有同等反馈。

**影响**：失败恢复困难；客户需记住提示、对照目录和重新挑选文件，容易漏处理或重复操作。未发现这段逻辑会删除失败文件，不能把反馈不足说成已经丢失文件。

**具体建议**：所有批量入口共用一次操作结果：成功数、失败文件名、原路径、目标、原因及“重试失败项”。成功时可保持轻提示；失败时保留可关闭的“查看详情”。保存本次会话的失败记录即可，不必让客户先配置规则或查看技术日志。不能重跑已经成功的文件，也不能静默覆盖同名项目。

**改进前后**：现在要自己找回失败项目和原因；改进后打开结果清单，处理占用或权限问题，只重试失败项。

### 4. 首次使用的“添加第一个收纳区”引导不会进入 — 优先优化

**场景和待实测步骤**：使用全新配置，没有收纳区、文件组或小组件；首次打开控制中心，判断第一步做什么。

**当前证据**：`src/stores/state.ts:794` 始终注册快捷启动；其默认布局隐藏。`src/manager/WorkspaceOverview.vue:12` 的 `surfaces` 仍包含它，所以 `selected` 非空，`v-else` 首次欢迎分支不出现。复核空工作空间得到 surfaceCount=1、firstTitle=快捷启动、welcomeShown=false（case `fresh_workspace_welcome_branch`）。这是分支逻辑证据，首次启动实际画面尚未截取。

**影响**：第一次使用的主任务偏向一个空且隐藏的快捷启动预览；客户虽然仍能使用“添加内容”，但需要自己判断入口及四类对象的差别。

**具体建议**：欢迎状态按是否存在用户创建内容判断，排除空且隐藏的系统启动栏。首屏直接给“新建收纳区”“显示已有文件夹”两个任务，说明“拖入会移动文件 / 只浏览不移动”。“按类型查看”和“组合来源”保留在“更多整理方式”，不必删掉能力。创建成功提供“到桌面开始整理”，说明真实移动后果；不预先移动任何用户文件。

**改进前后**：现在先理解空预览，再找添加菜单；改进后按自己的任务选入口、输入名称或选文件夹、开始使用。

### 5. 固定快捷入口成功，日常使用的启动栏仍找不到 — 优先优化

**场景和待实测步骤**：保持默认启动栏隐藏；搜索一个常用文件；点“固定到快捷启动”；回到桌面寻找刚固定的入口。

**当前证据**：`src/stores/state.ts:1845` 的 `pinEntry` 保存引用并提示成功，不改变显示状态、不提供后续动作。复核新增入口后 visible 仍是 false（case `first_pin_hidden_launcher`）。`LauncherManagement.vue` 有入口管理，但没有此页的启动栏显隐按钮；恢复依赖概览或布局设置。

**影响**：客户完成了设置，却需要再找“在哪里显示”，增加一次配置寻找和页面切换。

**具体建议**：保留已经明确选择的默认隐藏策略。成功提示加“显示桌面启动栏”动作；快捷启动页增加“在桌面显示”开关及“查看启动栏”按钮。用户明确选择后持久保存，不在每次固定时擅自弹出启动栏。

**改进前后**：现在固定后还需到概览或布局中找恢复；改进后从成功提示一步显示，之后每天直接使用。

### 6. 待办编辑草稿与“内容会自动保存”说明不一致 — 优先优化

**场景和待实测步骤**：组件 → 编辑待办 → 点击已有任务文字 → 修改 → 未点保存就关闭弹窗或切到桌面空间 → 再打开。另测编辑期间任务在另一窗口被改动。

**当前证据**：`src/manager/WidgetManagement.vue` 的编辑弹窗统一说明“内容会自动保存”；`src/components/TodoList.vue:17` 把任务修改保存在局部 `editText`，只有 `saveEdit` 才写回。导航采用条件挂载，没有离开时的草稿保留或未保存拦截。弹窗关闭后的组件挂载行为需实测；切换整个管理模块导致组件卸载的路径能从代码确认。并发冲突提示要求取消后重新编辑，客户需要自行保留草稿。

**影响**：客户可能把“已输入”当成“已保存”，丢掉此次修改并重复录入。不是已保存任务被删除。

**具体建议**：说明改为“新增和完成状态自动保存；修改文字请按 Enter 或点击保存”，编辑时显示“尚未保存”。模块切换、隐藏组件和关闭编辑器时保留草稿；涉及空内容或并发冲突时不能自动提交。冲突中同时保留草稿与最新文本，提供“复制我的草稿 / 查看最新内容”，保留明确的业务判断。

**改进前后**：现在依赖客户记住不同保存方式；改进后保存状态明确，离开后可续写，不用重复录入。

## 已经简单、应当保留的设计

以下是代码和需求层面确认的优点，原生体验尚待验证：

- 默认共存、首次不自动移动桌面文件，也不要求先创建整理规则。
- 新建收纳区主要只需名称；已有文件夹默认只浏览，选择路径可带出名称。
- 单栏搜索就地展开，普通单选不弹出批量工具栏；多选再出现操作，避免常驻配置负担。
- 快捷启动只保存引用；失联入口保留且可重绑，不把暂时拔盘当作永久删除。
- 待办固定添加框、Enter 连续添加、添加后保持焦点；完成任务折叠、删除可撤销，适合日常重复使用。没有需求依据增加日期、标签、优先级或流程审批。
- 解散收纳区先放回文件，失败时保留对象；删除小组件有内容损失确认。这些保护不能为了少一次点击而取消。
- 配置备份清楚说明不包含原文件及剪贴板，恢复前做备份，保留现有收纳目录。

概览中的文件和待办是只读预览。将来可考虑复用实际打开、完成任务动作以减少跳转；本轮没有视觉或用户行为证据证明客户一定误点，因此不把这一点列为必须修复问题。

## 客户交付前必须补齐的实测

解除浏览器已保存的拒绝权限后，可先完成隔离页面的实际操作与截图。正式交付仍需独立 Windows 测试实例，使用明确可丢弃的测试文件：

1. 全新配置启动，创建空收纳区，不改变现有桌面文件；创建后能输入、找到并开始整理。
2. Explorer 拖入、内部跨区移动、拖出、放回桌面；磁盘正确份数及内容一致；拖放取消无移动。
3. 同名文件、被占用文件、权限拒绝、部分成功、重试失败项、解散失败；文件不会被覆盖或丢失。
4. 真正的中文输入法、其他应用在前台时全局搜索、Esc 归还焦点；慢索引补入保持选中项，Enter 打开正确文件。
5. 固定后显示、移除引用不删原文件，断盘入口保留并可重绑；真实应用启动参数有效。
6. 待办连续录入、修改后离开、空内容、并发冲突、删除撤销、隐藏/重启/恢复，内容与显示一致。
7. 已布局及锁定对象的查看/恢复，多屏负坐标、不同 DPI、拔屏再接回，不随意改写正常布局。
8. 旧配置、缺失映射路径、跨机导入、恢复前快照、两个窗口同时修改；配置一致且文件完整。

本轮未实施上述改进。需要用户确认优化范围后，才修改产品代码并回归原有需求。
